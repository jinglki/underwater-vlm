# 从 mama-main 迁移到 AquaRoute

## 原样保留

- 桌面 `model.py` 与 `pipeline.py` 和 mama-main.zip 中对应文件逐字节相同，已确认没有版本冲突。
- `mama/*.py` 全部保留，包括模型、count 解析器、编排、评估、增强、预处理和历史 CLI。
- `config/config.yaml` 保留原样，不把新配置伪装成已完成实验的配置。
- `enhance/waternet/` 的源码、权重、许可证和示例资源原样保留；仅在分发时排除 `.git` 与 `__pycache__`。
- 30 个保护文件的 SHA256 列于 `preserved_sha256.json`。

## 新增和修复

1. 根目录项目名为 AquaRoute，保留原文件夹层级和四个执行阶段。
2. 新识别入口与旧 count 分离；presence 不再被要求输出数量或位置；classification 使用明确的候选标签。
3. 新配置指向 Qwen3.5 9B，修复原始配置的 `mdoels` 拼写并直接使用随包的 WaterNet 权重位置。
4. 识别批量生成默认 8 个独立条件，CPU 并发读取图片，OOM 时拆分重试并降低后续批次。
5. 新 Processor API 将 padding 放到 `processor_kwargs`；旧接口仍保留兼容分支，不通过屏蔽日志掩盖错误。
6. 识别结果逐批保存；通过锁、输入校验与元数据防止重复写入和不匹配恢复。
7. 清单、标签、条件、图片顺序与输出类型在模型加载前或解析时校验。
8. 识别评估区分有效回答与全样本，并补充真实类别分布与多数类基线。
9. README 改写为中文运行说明，添加分阶段运行、已有 prepared 复用、迁移、测试与故障排查。

## 迁移步骤

1. 将 AquaRoute 解压为新目录，不覆盖正在运行的旧项目。
2. 将已有模型目录复制或软链接到 `models/`，保留正在使用的 Python/CUDA 环境。
3. 已完成的 count 预测和指标无需修改。若要复现，先记录原服务器配置及版本，不能假定归档里的 4B 配置就是之前 9B 的实际配置。
4. 若直接使用已有增强图，复制 prepared 文件或引用原路径，必要时用 `--path-map` 显式映射；不重跑增强。
5. 用识别 `infer --limit 16` 检查真实模型输出，再使用相同 run-id 执行 `infer --resume`。

## 当前边界

批次增大不会保证成倍提速，也可能使浮点计算和逐条结果产生差异。识别和 count 使用不同提示词，必须作为不同任务记录。
增强算法保留，所以 Zero-DCE 的随机优化、WaterNet 逐图加载等既有性能特征仍存在。
本次没有拿到真实模型权重、全部图像和服务器运行环境，不声称完成 GPU 全量验证。
